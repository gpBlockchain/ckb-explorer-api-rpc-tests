# V2 Bitcoin 索引活动统计正确性用例评审

评审范围：核对 Explorer 按半小时写入的 Bitcoin 新地址和新交易计数时间序列
源码版本：`develop@0495ecd00a839f7618bad752f5ad92071124a991`

## 接口说明

- 接口作用：按时间升序返回 Bitcoin 索引活动统计，每条记录包含半小时窗口内新建 Bitcoin 地址和交易数量。
- 输入：`GET /api/v2/bitcoin_statistics`；事实基准为可读取相同索引 `created_at` 时间的统计快照，不以 Bitcoin 区块时间替代写入时间。
- 成功结果：返回所有已保存统计点，时间升序，计数与 `[窗口结束时间-30分钟, 窗口结束时间]` 内的索引记录一致。
- 失败结果：无统计记录时返回空数据；独立索引快照不可用时该次正确性 oracle 不可用。
- 不负责：Bitcoin 链上每半小时出块/交易数、后台调度准点性、缓存头和实时未持久化活动。

## 待评审用例

| 用例 | 场景 | 预期结果 | 防止的问题 | 优先级 |
| --- | --- | --- | --- | --- |
| `BTC-STATS-RPC-01` | 索引中存在多个不同 timestamp 的 BitcoinStatistic 记录，调用统计接口 | 每条返回记录的 timestamp、addresses_count、transactions_count 与已保存统计点一致，记录按 timestamp 升序排列 | 字段串位、计数类型错误或时间序列倒序导致图表失真 | P0 |
| `BTC-STATS-RPC-02` | 在一个统计点的开始边界、窗口内部、结束边界以及结束边界之后分别创建 BitcoinAddress 和 BitcoinTransaction 索引记录，再生成该统计点 | 开始和结束边界均计入，窗口内部计入，结束边界之后不计入；地址数与交易数分别独立统计 | 半小时窗口开闭边界错误造成稳定的少计或多计 | P0 |
| `BTC-STATS-RPC-03` | 统计生成发生在任意分钟，窗口结束时间包含当前年、月、日、时、分，秒归零 | 保存和返回的 timestamp 等于该分钟 UTC Unix 毫秒值，统计开始时间精确早 30 分钟，不因时区或秒/毫秒混用偏移 | 时区、分钟对齐或时间单位错误使数据落到错误图表桶 | P1 |
| `BTC-STATS-RPC-04` | 对同一窗口结束 timestamp 重复生成统计，期间窗口内索引记录数量发生变化 | 仍只有一个该 timestamp 统计点，两个计数字段更新为再次生成时的窗口计数，不产生重复时间点 | 重试或任务重放生成重复数据，或旧计数无法纠正 | P1 |
| `BTC-STATS-RPC-05` | 数据库没有任何 BitcoinStatistic 记录 | 接口成功返回空数据集合，不虚构零值时间点或继承旧缓存记录 | 新环境或统计尚未运行时展示伪造历史 | P2 |
| `BTC-STATS-RPC-06` | 正确性测试无法读取与 Explorer 相同的索引 `created_at` 快照，只能访问 Bitcoin 链上时间 | 将本次统计 oracle 标记为不可用，不用区块时间近似值判定 API 计数错误 | 把索引写入活动误当链上活动并产生不可复现的差异 | P1 |

## 本轮需要确认
