# V2 DAS 反向账户查询正确性用例评审

评审范围：批量查询 CKB 地址对应的 DAS 反向记录，并用对应环境 DAS Indexer 逐地址核对结果
源码版本：`develop@0495ecd00a839f7618bad752f5ad92071124a991`

## 接口说明

- 接口作用：接收一组 CKB 地址，返回以原地址为键、DAS account 为值的映射。
- 输入：`POST /api/v2/das_accounts`，请求字段 `addresses`；事实基准为对应环境 DAS Indexer `POST /reverse/record`。
- 成功结果：有效 DAS 地址逐项返回反向记录；非法地址不进入结果；有效但不使用 DAS 支持算法的地址返回空名称。
- 失败结果：DAS Indexer 返回业务错误时该地址映射为空名称；独立事实基准不可用时只标记该网络的本次核对不可用。
- 不负责：DAS 注册、所有权变更、正向解析、缓存时效、通用 HTTP 与响应头契约。

## 待评审用例

| 用例 | 场景 | 预期结果 | 防止的问题 | 优先级 |
| --- | --- | --- | --- | --- |
| `DAS-RPC-01` | 在对应环境提交多个格式有效、使用 DAS 支持算法且已设置反向记录的 CKB 地址 | 响应以每个原始地址为键，值与 DAS Indexer 对同一地址返回的 account 完全一致；不同地址的结果不串位 | 地址参数截取、批量映射错位或连接错误 DAS 环境导致账户名对应到其他地址 | P0 |
| `DAS-RPC-02` | 同一批请求同时包含有反向记录的有效地址、无反向记录的有效地址和格式非法地址 | 有记录地址返回其 account；无记录地址按 DAS Indexer 结果返回空名称；非法地址不出现在映射中，且不影响其他地址成功返回 | 单个坏地址使整批失败，或非法输入被发送给上游并污染有效结果 | P1 |
| `DAS-RPC-03` | 提交格式有效但 Lock Script args 算法 ID 不是 `0x05` 的 CKB 地址 | 该地址保留在响应映射中且值为空字符串，不产生虚构 DAS account | 把其他地址算法误当作 DAS manager 地址并返回错误账户名 | P1 |
| `DAS-RPC-04` | 批量查询中一个有效 DAS 地址收到 Indexer `err_no != 0` 的业务错误，其他地址正常返回 | 业务错误地址的值为空字符串，其他地址仍分别返回自己的 account | 一个地址的上游业务错误清空整批结果或泄漏为其他地址的结果 | P1 |
| `DAS-RPC-05` | 用独立 DAS Indexer 核对 API 结果时，该网络的 Indexer 超时、返回非 JSON 或暂时不可达 | 将该网络的本次事实基准标记为不可用，不把缺少 oracle 判定为 Explorer account 不匹配；另一网络结论不受影响 | 上游短暂故障被误报为产品数据错误，或一个网络阻断全部结论 | P1 |
| `DAS-RPC-06` | 请求省略 `addresses`，或将其提交为非地址数组类型 | 待确认：接口应返回哪一种稳定的客户端错误状态和错误对象，而不是由参数类型触发未定义的服务端异常 | 缺少输入契约导致调用方无法区分请求错误与 DAS Indexer 故障 | P1 |

## 本轮需要确认

- `DAS-RPC-06`：缺少或类型错误的 `addresses` 应采用哪一种稳定客户端错误契约。
- 其余用例的结果可由当前控制器、地址解析器和 DAS Indexer 返回语义确定。
